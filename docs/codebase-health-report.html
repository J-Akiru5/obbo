§4 Discrepancy Register

Verified this session against HEAD e7e3b61 and the live DB. Severity is impact-weighted for a fresh DB / new-order flow.

S-1schema.sql has a fresh-install ordering bugcriticalsupabase/schema.sql:221

delivery_receipts.order_id gets a FK to public.orders(id) at line 221, but the orders table is only created at line 224. On a truly empty database, schema.sql fails with relation "public.orders" does not exist.

Fix: move the ALTER (or use ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY after both tables exist).
S-2shipment_ledger.delivery_receipt_id not in canonical schemacritical.agents/migrations/017 · supabase/migrations/20260720_dispatch_order_rpc.sql

Written by dispatch_order_v2() (step 6), typed in database.ts, and read by ledger/DR code — but absent from schema.sql. A DB built from schema.sql + dated migrations fails to dispatch. It's live in prod (so 017 was applied there), but any fresh/staging DB breaks.

Fix: absorb 017's column + FK + index into schema.sql.
S-3No reproducible/ordered migration path — 3 parallel lineagescritical.agents/migrations · supabase/migrations · supabase/*.sql

~32 SQL files across 4 locations with no applied-tracking. Production is a hand-applied subset (e.g. 002+017 applied, 005 not). prisma/migrations/ is empty and prisma migrate deploy would deploy nothing. This is the root cause of S-1/S-2 and makes any environment rebuild a manual, error-prone procedure.

Fix: consolidate into one dated supabase/migrations sequence that replays on schema.sql, and delete the dead Prisma model + generated client.
S-4order_items.selling_price_per_bag missing from OrderItem typehighsrc/lib/types/database.ts:185

The column is written by client-actions.ts:230 / admin-helpers.ts:181,192, exists in schema.sql + migration 20260629 (now applied to prod), but the OrderItem interface omits it — so readers are forced to re-read products or use any.

Fix: add selling_price_per_bag: number | null to OrderItem.
S-5email_verifications is live but undeclaredhighsrc/app/api/auth/{send-otp,verify-otp}/route.ts

S-6TrackingStatus type omits returned_good / returned_wastehighsrc/lib/types/database.ts:19
